# Social Creative learning library

Updated 2026-11-06. This is the master retrieval index for our retained research, production methods and working patterns. Detailed evidence remains in the linked owning documents; this index does not replace them. Personal taste, client assets and campaign results remain with the active project.

## Pull the right learning into a task

1. Read the active project's brief, current instructions, selected references and explicit feedback.
2. Use the topic tables below, or the relevant skill's packaged learning index. Read the matching source record and working method, including its coverage and limits.
3. Adapt the method to the task. Retrieve a working template when useful; an untested idea is a study candidate.
4. Save the actual version, feedback, verification and next decision with the project. Update an existing record when evidence changes rather than adding contradictory copies.

From this repository, a focused search is enough:

```sh
rg -n -i 'luma|matte|paper' skills/video-editor/references skills/video-editor/assets/cross-grid
rg -n -i 'quote|carousel|editable' skills/social-designer/references
rg -n -i 'baseline|audience|experiment' skills/social-content/references skills/social-marketer/references
```

Inside an installed standalone skill, search its own `references/` and `assets/` directories. No database or external service is required.

## Read evidence on separate axes

- **Inspection:** full audiovisual review, sampled frames, transcript, caption, documentation or unavailable.
- **Implementation:** researched, guidance integrated, working source, render checked, alternate inputs checked or not implemented.
- **Acceptance:** explicit acceptance for a named context, pending, rejected or superseded. Keep the reason unknown when the user has not supplied it.
- **Performance:** measured project outcome with a relevant baseline, hypothesis or unknown. Visual preference and successful tests are not performance evidence.

A source may be partly inspected while an original adaptation renders successfully. Those facts can coexist; neither establishes mastery of the source creator's full method.

## Maintain the library

For each new learning, keep the source/date, actual inspection, transferable technique, appropriate contexts, owning method/template, validation, user feedback where applicable, limits and next check. Add a short catalogue entry and a link in the owning skill's learning index. Keep detailed evidence in one owning file. Correct/supersede stale claims and retain why an approach was rejected.

For project taste, update the existing reference library/brief and, where available, index it with the project's skill-learning helper. Do not export private client taste or assets into this generic plugin. Keep project artifacts in durable project storage when their task worktree is archived; preserve or repair their evidence pointers.
