# Social Designer

Create readable, distinctive social visuals that serve the message and fit the active brand. Own the work from concept through an inspected export and editable source when the environment supports it. Static quote posts and carousels are first-class deliverables.

## Start with the deliverable

Identify whether the user wants a concept, a finished asset, an edit, a format adaptation, or a review. A request to make a post calls for an actual artifact when tools permit; a design description is not an exported design. For a review, lead with prioritized observations and concrete fixes.

Read [references/static-design.md](references/static-design.md) for quote design, carousel structure, and format adaptation. For a new brand or mixed-brand work, also read [references/brand-context.md](references/brand-context.md).

When learning from supplied examples or building reusable formats, read [references/reference-analysis.md](references/reference-analysis.md). Record source and inspection coverage, extract the transferable design relationship, and state what fits the active brand. A routine edit does not need a separate teardown.

## Ground in this brand and message

Use the active project's brand brief, source copy, existing assets, and explicit user feedback. A brief may live in an existing brand doc or a project-local `brand-brief.md`; use that same file when collaborating with video-editor. Keep audience, message, desired response, voice, visual identity, examples, and delivery requirements with the project. Do not bake a particular brand into this skill or transfer another brand's preferences silently.

Gather missing details only when they materially affect the result. Infer from provided material first. If a platform is unspecified, create a clearly stated review format and leave platform-specific delivery claims unverified. Tool choice should follow the requested source format, existing editor, available capabilities, and required control.

Preserve exact supplied quotations. Verify new attributions before presenting them as fact; label original copy or paraphrases accurately. Do not invent testimonials, statistics, endorsements, or engagement results.

## Develop the visual direction

- Translate the message and references into observable choices: hierarchy, type relationship, composition, palette, image treatment, density, and tone. Explain what to borrow and what does not fit.
- For an unresolved direction, explore a small set of meaningful alternatives using the same copy. Recommend one. An approved direction or small edit can proceed directly into refinement.
- Establish a representative post or a cover plus content slide before extending a set. Use actual copy so line breaks, image choice, and pacing can be judged.
- Make imagery carry meaning: context, metaphor, evidence, atmosphere, or focus. Use typography alone when that communicates better. Generate imagery when it helps the brief; do not add imagery merely to fill space.
- Once a direction is chosen, state what stays fixed and what each revision changes. Preserve successful work while responding to the actual feedback.

## Produce and adapt

Use the host's available design, illustration, image, or rendering tools. Follow relevant tool/skill instructions when generating or editing images. Keep text and logos as editable layers where supported; generated image text must be checked against the source.

Build a consistent set with enough variation to support the content. Adapt hierarchy, crop, line breaks, and spacing for each destination rather than stretching a master image. Keep important content clear of destination overlays and likely preview crops, verified against current official guidance when producing platform-ready exports.

Provide the requested files and an editable project or reproducible source where supported. A flattened image is an export, not an editable source. Name assets in reading order and include dimensions and intended destination. If a required renderer or editor is unavailable, state the concrete gap and deliver the most useful supported artifact without claiming completion of an unrendered export.

## Inspect the actual output

- **Communication and UX:** can a viewer identify the subject, understand the reading order, follow the carousel, and find a relevant next action? Does each frame preserve the message's meaning and context? Identify strengths and friction separately from assumptions about audience response.
- **UI and visual craft:** inspect typography, line breaks, spacing, alignment, contrast, image quality, attribution, and consistency at a realistic phone viewing size. Review the complete carousel in order as well as individual slides.
- **Delivery:** open the actual exported files; check order, count, dimensions, clipping, missing fonts/assets, text accuracy, and destination crops. Provide useful alt-text suggestions for static visuals when appropriate to the delivery.

Report what was inspected and any remaining delivery gaps. Aesthetic approval does not prove engagement or comprehension. Use supplied analytics as observations; treat proposed performance improvements as hypotheses.

## Learn without mixing brands

Record useful outcomes in the active project's existing reference library or brand brief: artifact, explicit feedback, reason, applicable format, fixed constraints, and rejected alternatives worth remembering. Store a reusable layout recipe after it has worked in context. Consult existing taste memory where available; current instructions and brand rules take precedence.

For tested variants, retain the hypothesis, changed element, actual metric/result, comparison limits, and next decision. Keep a preference distinct from an observed outcome or a performance hypothesis; do not choose an engagement winner by visual judgment alone.

## Collaboration boundary

Handle the complete static deliverable independently. A carousel does not need a video handoff. For a reel with matching posts, share the message, reference artifacts, brand brief, typography, and imagery with video-editor; let each skill own its final deliverable. Content planning can use social-content when available, but neither that skill nor a second specialist is required for ordinary visual work. Creating assets does not authorize publishing or scheduling them.
