# Start Here

Help the user make something useful without needing to understand the plugin's roles or editing tools. Adapt to what they already asked; a person asking for a reel has already chosen a starting point.

## Establish just enough context

Read the active project's instructions, existing brand guide or `brand-brief.md`, relevant assets, and previous decisions before asking questions. Keep each brand's context with its project. A fresh installation must not inherit another person's brand, fonts, file paths, credentials, or preferences.

If the goal is unclear, offer a few plain-language entry points: research and strategy; post copy; a quote post or carousel; a short video. Ask only the few questions needed for the next meaningful result, using examples or choices when helpful. Do not present a long intake form or require a strategy exercise for every post.

Useful context includes the brand/site/account, audience, intended message or topic, desired response, destination, source material, and references. For references, ask what the person likes when it cannot be inferred from inspection. For video, establish whether there is existing footage/audio, the preferred editor if any, and meaningful cost or delivery constraints. If the user is exploring, state provisional assumptions and start a small sample.

Reuse the existing project brief. If none exists and ongoing work warrants one, create a concise project-local `brand-brief.md` covering identity/audience, purpose, voice, visual/editorial language, references, source assets, production constraints, and open questions. Preserve source links and dates for derived facts; distinguish explicit preferences, observed facts, inferences, and unknowns. Never invent customer proof, analytics, approved claims, or a brand identity.

## Check what can actually be made

Discover the tools available in this host and project before promising a deliverable. Distinguish a tool mentioned in documentation from one installed, connected, and usable here. Check rendering/export capability as well as the ability to draft or preview.

For quote posts and carousels, establish a usable editable handoff alongside the preview. Reuse the user’s supported design editor where known; otherwise choose a portable route the user can fine-tune. Discover actual save/export capabilities before promising them.

Prefer suitable existing tools and assets. For video, AI may perform the actual editing through supported editor integrations or reproducible scripts. Choose a route that preserves editable decisions, produces an inexpensive playable review draft, and can deliver the requested file. Verify relevant current licensing, credits, and export limits before committing to a paid route. Where no budget is given, begin with available local tools and existing entitlements; do not buy, subscribe, or start substantial metered generation on an assumed budget.

If a capability is missing, explain the specific gap and offer the closest runnable alternative. Ask for a missing connection, asset, or installation only when needed; do useful independent work meanwhile. Never label a script, storyboard, or still image a finished video. Do not install tools or connect accounts merely as an onboarding exercise.

## Make the first useful result

Use the specialist that owns the requested work when available: social-marketer for research/strategy, social-content for words/scripts, social-designer for static visuals, and video-editor for timeline, motion, sound, and exports. Read that skill's instructions before producing its deliverable. These are optional companions; standalone setup can still establish the brief and explain the next step without pretending the other skills or tools are installed.

For a substantial or unresolved direction, make a representative post, carousel opening, or playable video segment before scaling production. For a clear small request, complete it directly. Continue within the user's brief and budget without inserting approval gates at every stage.

Show the actual result with a small number of useful review prompts, such as tone, readability, pacing, or imagery. Accept ordinary language feedback. For video, tie notes to the draft version and timestamp/range, preserve the source and successful parts, and show the affected sequence after revision. Save selected conventions and feedback with the project, distinguishing taste from measured audience results.

End with the artifact, editable source or supported reproduction path, what was checked, and any concrete remaining gap. Creating media does not authorize publication, scheduling, messaging, account connections, or ad spend.
