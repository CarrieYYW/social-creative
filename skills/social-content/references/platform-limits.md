# Platform Delivery Verification

Use when preparing destination-ready copy, captions, hashtags, covers, or production briefs. Technical limits and display behavior vary by surface, account tier, region, client, and release. This reference owns the verification method rather than a table of unmaintained numeric limits.

## Identify the exact surface

Record the destination, post type, organic/ad context, account tier where relevant, and whether delivery uses the native editor, a scheduler, or an API. A limit for an advertising placement does not automatically establish an organic-post limit; an API may impose different constraints from the native composer.

Verify only the fields needed for this deliverable:

| Field | What to establish |
|---|---|
| Text | Caption/post/title/description limits, counting method, and supported formatting |
| Tags | Hashtags, mentions, topic tags, applicable caps, and how they count toward text limits |
| Media | Supported file types, dimensions/ratios, duration, count/order, file size, and captions where relevant |
| Preview | Feed/profile crops, truncation behavior, overlays, cover selection, and meaningful first-visible content |
| Accessibility | Available alt text, captions, descriptive copy, and how they survive the chosen publishing path |
| Delivery | Any native-editor, account-tier, scheduler, API, or placement-specific restrictions |

Do not confuse a technical maximum with a recommended target. Copy length, tag count, and slide count should serve the content and audience. Preview truncation can depend on layout and device; a remembered character count is not a reliable preview check.

## Verify with current official guidance

Use the destination's current help, business, or developer documentation for the exact surface. For example, check Meta/Instagram/Facebook help, LinkedIn Help, X Help, TikTok Support, YouTube Help, Pinterest Help, or Threads/Meta help as relevant. Check the actual composer or upload preview when available and within the user's authorized scope, without publishing as part of verification.

Keep the checked date, direct source URL, applicable surface/account context, confirmed requirements, and uncertainties in the project's delivery notes. A community recommendation is not an official limit. Avoid copying platform-wide performance claims or hashtag advice into a technical specification.

## Deliver with an honest verification status

Check actual copy and assets against the verified requirements, including tags and other text that count toward the total. Inspect previews and reading order at a realistic device size when available. Check accessibility text separately from decorative display text.

If a limit cannot be verified, state the assumption and unresolved requirement; provide a clearly labeled draft/review asset instead of claiming platform readiness. A technically valid file or text length does not establish audience performance. Retain enough context to recheck the destination before a later publication or adaptation.
